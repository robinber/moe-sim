# Cross-review v2: M0 global-capacity validation

## 1. Verdict: Approve-with-nits

No P0 or P1 correctness issue was found on the assigned axes.
`cargo test --workspace` passes all 26 unit tests and the doctest target.

## 2. Findings by axis

### Axis 1 — Correctness of the validation algorithm: none

- The manifest pass runs first over deterministic `BTreeMap` key order and
  rejects all oversize experts, including unreferenced entries.
- Both expert and active-set comparisons use `>`, so exact fit is accepted.
- A zero budget succeeds only for an empty manifest; events can then contain
  only empty active sets without producing an unknown-expert error.
- Canonical `Event` construction guarantees unique expert IDs, so
  `active_set_bytes` sums one atomic active set without double-counting.
- Active-set addition is checked; `u64` overflow returns
  `ManifestError::ActiveSetBytesOverflow` wrapped in `CapacityError`.
- Missing `(layer_id, expert_id)` entries return a typed unknown-expert error.
- Events are evaluated in supplied order; metadata is not used to reorder
  them.

### Axis 2 — Error taxonomy and context completeness: P2

The taxonomy is correct: intrinsic manifest construction/lookup/sum failures
remain `ManifestError`, while run-relative feasibility failures use
`CapacityError`. Expert failures include key, size, and budget; event failures
include zero-based `event_index`, `request_id`, `layer_id`, and either the
active-set total plus budget or the underlying manifest error.

P2: tests compare the nested `source` value but do not directly assert the
`std::error::Error::source()` chain generated by `thiserror`. The implementation
is correct because the field is named `source`; a focused assertion would pin
that caller-visible contract.

### Axis 3 — Adversarial and test-gap analysis: P2

Coverage is strong and includes deterministic first-expert selection,
manifest-pass precedence over an independent event failure, exact fit,
unreferenced experts, overflow, layer-scoped sums, and file-order behavior.
The remaining gaps are listed in section 3; none exposes a current algorithm
bug.

### Axis 4 — Fail-closed behavior: none

Within `validate_global_capacity`, every bad configuration path returns `Err`:
oversize manifest entry, unknown expert, active-set overflow, or oversize
atomic set. The function returns only `()` on success and has no output or
mutable simulation state, so it cannot emit partial or soft-success results.

M0 still relies on future callers to invoke this validator before replay, but
there is no replay/result-emission path in the reviewed inputs that can bypass
it today.

## 3. Test gaps

All are P2 hardening opportunities:

1. Add a direct zero-budget rejection case with a positive-size manifest. The
   current tests cover zero-budget success and general oversize rejection, but
   not their exact intersection.
2. Put an unknown expert or overflow in a later event and assert a non-zero
   `event_index`. Non-zero indexing is tested for
   `ActiveSetExceedsGlobalCapacity`, but not for `ActiveSetBytes`.
3. Assert `std::error::Error::source()` for `CapacityError::ActiveSetBytes` to
   preserve the error-chain contract independently of field equality.
4. Optionally use an instrumented iterator to prove the event pass stops at
   the first error and never consumes later events. The current control flow
   already does so through `?` / early return.

## 4. PR-ready for your axes? yes

The validation algorithm, error payloads, and fail-closed behavior satisfy the
approved design. The listed gaps are non-blocking P2 test hardening.
